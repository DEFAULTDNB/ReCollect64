UPDATED SummerCart64: Save States & More

Modded by John Steinmeyer ~ Sep 16, 2026
SummerCart64: Save States!

Saving Your States

The Nintendo 64 is not a modern console by any stretch, so the news that modern features such as save states have been made a reality on the console is nothing short of mind blowing.

By leveraging the added memory of an Expansion Pak, John Steinmeyer has managed to eke out save states, a virtual Controller Pak, suspend/resume and slow motion for the SummerCart64, by modifying the hugely successful open-source N64 Flashcart Menu.

 

This fork adds, for the SummerCart64:

+ Save states. Hold L + R + D-pad Up in a game to save, L + R + D-pad Down to load, R + Z + Start for a slot panel with thumbnails; states persist on the SD card. Nothing stays resident in the console's memory, so games that use the whole Expansion Pak work too.

+ A virtual Controller Pak (memory pak). A game that uses one gets a pak that lives on the SD card, whether or not a real one is plugged in; on by default for the games known to use one.

+ Suspend and resume. Suspend a game to a slot from the panel and switch the console off; the next launch of that game picks up where you left it.

+ Slow motion and frame step, as a per-game option.

NOTE: It needs an Expansion Pak and works with 276 of the 298 games tested so far.

What you need:

+ A SummerCart64.

+ An Expansion Pak. The top 128 KiB of it is the working room the routine borrows during a save or a load (and gives back, byte for byte, before the game runs again), so states are not possible on a 4 MiB console.

+ ROMs up to 48 MiB. The states are kept in the cartridge memory above the ROM; the bigger the ROM, the fewer slots fit, and a 64 MiB ROM leaves no room at all (the option refuses to switch on for those, and such a game gets no virtual pak either).

+ Free space on the SD card: about 8 MiB per slot per game, allocated the first time a game boots with save states on (48 MiB for a game with six slots), and 32 KiB per game for its virtual pak.

How to use:

+ Select ROM, open options, choose save states and toggle enable.

I will be testing this in the coming days and will update this article with my findings!

UPDATE: 17/09/2026 - Having given this a full testing this morning here are my results:

OG N64 Hardware:

Everything works as directed! Save/load states and the save state menu interface are an absolute godsend and virtual controller pak emulation is an incredible feature too if you're short on real memory paks!

Analogue 3D:

Save/load states and the save state menu work perfectly but using virtual controller pak doesn't seem to register anything at all.

M64:

Neither save states nor virtual controller pak works, which is unfortunate because this could have seriously bridged the gap for virtual controller pak support that remains missing from the official firmware.

UPDATE: 18/09/2026 - 1.2 has been released with some changes and new features:

The GUI panel hotkeys are R + Z + Start now.

Save states for libdragon homebrew. I've tested about forty ROMs: FlappyBird, Kraken64, Legend of Elya, Junk Runner 64, Cathode Quest 64, VoidStrider64, Driving Strikers 64, nineteen of the N64brew Game Jam 2025 entries and most of the SDK examples. Games with the pre-2023 entry code run without the routine.

The virtual Controller Pak's port is yours to pick (Port 1 to 4, or Off), and the panel can pull the pak out and put it back in any port mid-game. Beetle Adventure Racing gets its Controller Pak for saving and its Rumble Pak for racing that way, and Perfect Dark takes a Rumble Pak in port 1 with the pak in port 2.

Hotkeys are configurable, one button or more each, for all games or per game.

Screenshot button, per game. A tap writes a PNG to sd:/screenshots//. Hundreds per launch.

Frame step without the lag: one press, one frame. Hold to step ten a second.

The image viewer steps through a folder, the file browser previews images, and a background image fills the screen.

Slow motion is refused for the four games that use all of the Expansion Pak, since they never booted with it on.

Fixes: the panel in interlaced modes, a hotkey tap leaking to the game, the RDP's pipe-busy flag blocking saves, games that poll a masked interrupt, resuming on the vblank, a state saved with Slow motion off not loading after a power cycle with it on, and a few libdragon ones. The changelog has the full list.

UPDATE: 18/09/2026 - 1.3 has been released with some changes and new features:

Saves move between a game's virtual Controller Pak and a real one, from the menu: single notes either way, or whole paks, from any port. Start in the file browser (Virtual Controller Paks) or in a game's options (Virtual Controller Pak, Manage saves). The real pak is backed up to sd:/cpak_saves before it is first changed. Asked for by Tom Scro on Discord.

The virtual pak's port list shows what is plugged into each port, live, and refuses a port holding a real Controller Pak. A Rumble Pak there is fine.

A fix for the screenshot button: a tap at the wrong instant could stop the game's sound, or the game, and quick taps in a row found that instant before long. A screenshot is taken at the same kind of moment as a save now.

Built on N64FlashcartMenu 0.3.4, whose one change fixes crashes in Ocarina of Time by resetting the video registers before a game boots. Games built with libdragon skip that reset: libdragon's display setup waits for a vblank when it finds the VI switched on (the stable branch since August 2023, the preview branch until April 2025), and with every timing zeroed that vblank never comes, so FlappyBird stayed on a blank screen. Newer preview builds cope. A ROM with Nintendo's boot code still got the full reset, so a stable-branch build from before October 2024 stayed blank; 1.4 covers those.

AeroGauge, BattleTanx, BattleTanx: Global Assault and Cruis'n World work; the compatibility list said otherwise.

UPDATE: 19/09/2026 - 1.4 & 1.5 have been released with some changes and new features:

ROM autoload is back. In a ROM's information screen, R, then "Set ROM to autoload", and the console boots straight into that game from then on, with the routine armed as on any launch. Hold Start while switching the console on to get the menu back; that switches autoload off as well. Upstream dropped it in 0.3.0 for Fast Reboot and has brought it back on its develop branch; this build follows, and the Fast Reboot setting is gone with it, as there.

Banjo-Kazooie booted with a black sky and a thin strip of ground in 1.2 and 1.3, with Save States on and Slow motion off. Since 1.2 the routine kept a counter on a word in low memory that the game's copy protection checks against its boot code, and a wrong word there makes the game sabotage its own perspective setup. The counter lives elsewhere now. With Slow motion on the routine is placed differently and the game was fine, which is how it went unnoticed here. Reported by Acurrz, who also confirmed the fix.

The video reset before a game boots switches the VI off as well, the state it is in at power-on, for every ROM that gets the reset. libdragon homebrew built on the stable branch before it shipped its own boot code carries Nintendo's, so 1.3 gave it the full reset and its display setup waited forever for a vblank. With the VI off it does not wait.

The freeze after a load is fixed. Since 1.2 a state could be saved while the RDP was still finishing the frame: the test that picks the save moment had stopped counting the RDP's pipe flag, a change made for libdragon homebrew, whose frames never clear it, but applied to every game. In such a state the frame's final interrupt was still owed to the game, and a load never delivered it, so the game waited forever: Wave Race 64 on about one load in three, Banjo-Kazooie on one in five. The flag counts again for games that clear it, so the moment comes once the frame is done, as in 1.1; libdragon games are unchanged.

States saved by 1.2 to 1.4 at such a moment load as well: the load runs the frame's closing command itself and the interrupt arrives. The files do not change; hook version 13 marks the states written with the new rule.

The Menu information screen (Start, then Menu information) now opens with the save states release, this repository and the base menu's version, so a report can quote that line; the build timestamp below it pins the build.

UPDATE: 20/09/2026 - 1.6 & 1.7 have been released with some changes and new features:

The vertical jitter with the virtual pak on is fixed: Tony Hawk's Pro Skater 3 at its boot and in its menus, Perfect Dark at its logos, in their high-resolution modes. With Slow motion off the routine runs from the cartridge, slowly, and three things it did around a pak transaction held the console's interrupts too long there, so the game's video interrupt came up to 3 ms late, past the vertical blank of a high-resolution mode: a walk over the memory after the game's controller block, looking for buttons that were not there; the checksum of every pak read, computed a byte at a time; and a wait for the game's own cartridge transfer to end before the read could be answered. The walk is gone, the checksums come from a table the menu prepares when it loads the pak, the wait is a hand-off (the transfer's end brings the read back), and a pak presence check, which some games make a hundred times a second, is answered without the rest of the machinery. Reads are cheap now, so the logos and the menus hold still. A write to the pak still costs the routine about a millisecond from the cartridge, so a game that writes to its pak as it starts keeps a mild jitter for a second or two there and nowhere else: THPS3 tests the pak with fifty writes at its legal screens, Perfect Dark touches its save at its logos. With the virtual pak off for the game that goes too. THPS3 adds one late frame of its own at its pak check, by switching interrupts off there.

Tony Hawk's Pro Skater 3 refuses Slow motion, as the other games that use all of the Expansion Pak do: its high-resolution mode did not boot with it on.

States and pak files do not change; hook version 13 as in 1.5.

Hotkeys for every game at once. On a game's Hotkeys and Screenshot page, after the hold, A keeps the buttons for that game and Z gives them to every game: the ones you set up one by one before included, and any game you add later. A game's own set after that still wins for it. The screenshot button works the same way, and the menu's Save State Hotkeys page has it now too. DEFAULTDNB asked for this one.

A game's options menu stays open after a setting, and comes back after the Hotkeys and Manage saves pages, so several changes go in one visit.

The Virtual Controller Paks view no longer crashes on a real pak holding a note with a byte outside the pak's character set in its name; the byte shows as a ? now. Reported by Tom Scro, with the dump that named it. He also found that a controller whose pak cannot come out (a Switch Online controller through a BlueRetro adapter) launches with the virtual pak once it is in its Rumble Pak mode; that is in the notes now, as is when a game's pak writes reach the card (about a second and a half after the last one, the LED blinking; keep the console on for that). A hand-copied pak file of the wrong size in the paks folder is left alone, with a message, instead of being replaced.

States and pak files do not change; hook version 13 as in 1.5.
