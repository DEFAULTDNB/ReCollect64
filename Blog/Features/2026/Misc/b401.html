SonicDcer, aka Sonic Dreamcaster, has delivered yet again, and on his birthday no less! This time he has hand-ported one of the N64's fastest racers to Windows PC, macOS, Linux and Flatpak platforms. With zero AI involved, this project has taken a few weeks to evolve into a playable state, but with a highly skilled human leading the entire project, it is far more easily maintainable, updatable, and moddable.

You may note that a public repository for Extreme-G's deompilation is nowhere to be seen. This is because the author has taken a different approach to this particular project, proving that even a partial decompilation is not entirely necessary for a recomp to live.

UPDATE: A word from SonicDcer:

Extreme-G Recompiled, how was this possible without a decomp project?

The answer is N64Recomp is a framework that makes it possible to make a port without decompiled source code.

Even though the majority of ports made with N64Recomp so far derived from partial or complete decomp projects, Extreme-G just happened to be the perfect showcase for this technology. N64Recomp isn't a magic black box that turns ROMs into ports, it rather needs to know the exact location and sizes of all the functions and data that compose the game, that metadata has to come from somewhere, usually an .elf file which can result of building a decompilation project, but there's also another way...

Where is the Extreme-G Decompilation project?

Oh it's here https://gitlab.com/sonicdcer/extreme-g but..

Well.. I wouldn't call it a decompilation project yet since barely anything in there is decompiled, what I made is know as a disassembly, which is the previous step of what composes a decompilation project.

In order to achieve that, some research has to be done to the game ROM itself, such as where is the code of the game, where is the data, where is the rodata, what are the vram addresses of each section, if the game has compressed code, a decompressed rom has to be made first, which was unfortunately the case for Extreme-G. It seems they compressed as much as they could to fit the game inside an 8 MB ROM. Some previous research revealed that the game was compressed with LZSS as well as LZHUF type compression. Initially the way i reconstructed the uncompressed rom was by breakpointing through the functions of the game while running it through an emulator. With a combination of Dynamic and Static analysis I was able to dump the uncompressed portions of the game from RAM.

After I had the uncompressed rom the disassembly was manually handled piece by piece, by reading the machine code and mapping the game code into sections, this process proved to be more difficult than I experienced with other games because this particular one was built with a toolchain known as SN, which has unusual code rodata/data/text sections as well as bits of compiler garbage to account for padding, the code and data inside it were also aligned in an unusual way making the disassembly incompatible with the current setup I had for other games. After those problems were solved/circumvented and all the SDK library functions identified in it, the disassembly was ready to produce an .elf file that was compatible with N64Recomp, but that wasn't the end, more research was needed to map the overall functionality of the game, figure out where some stuff is in code without any documentation can be very tricky.

The bare minimum things that were patched for this game to be in a decent state are:

+ Widescreen alignment of hud and menu elements for the bike select screen.

+ Widescreen fill of the fade transitions.

+ Simultaneous Controller Pak and Rumble Pak support

Awesome Assembly

When porting the game to modern formats, this port is constructed entirely through assembly code (ASM); there is zero decompiled code, and everything is done without any C patches. No original source code for this project was employed either, because it is likely stored under lock and key by the company that acquired the Extreme-G IP, among 184 other game properties, in 2006: Throwback Entertainment. Alternatively, the source code could have been lost forever through failing to be archived properly or simple data misplacement.

The latter may explain the lack of additional content or fixes within it's re-release for the ModRetro via Throwback Entertainment. Regardless, this recompilation gives the game yet more life by delivering huge quality of life improvements such as lightning-fast native 60 FPS framerates (and interpolated up to any framerates your monitor supports), modern controls, rumble support, widescreen support, splitscreen multiplayer and more to a wider audience than just those rocking the 30-year-old 64-bit console or it's modern FPGA counterparts.
