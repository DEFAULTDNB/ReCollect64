Turtle 64 Released

Information and Conversion

A brand-new, highy verbose and incredibly flexible Windows-based tool has been released that extracts ROM information from N64, Aleck64, iQue player and homebrew ROMs across a variety of categories, which also allows you to convert your ROMs singularly, or in bulk, to any of the three main formats (Z64/V64/N64). Not only that, but 64DD support is incredibly well articulated too with *.D64 and *.NDD supported, ROM/RAM and LBA bounds, MFS information and file listing, and conversion to .D64 and both .NDD formats!

Turtle64 is the work of Derek Turtle Roe, a developer and preservationist who is culminating all the knowledge and nuances of ROM evaluation from the best possible sources over the years and pulling it all together into one new Swiss Army Knife-like GUI that can do absolutely everything with unbelievable granularity. The current version available is the preview build, but it's startlingly feature-rich, accurate and well-rounded already.

 

A native Rust + egui desktop application for working with Nintendo 64 ROM images. Turtle64 was heavily inspired by two excellent community tools, ROM64 and romjudge, and aims to carry their spirit forward in a single cross-platform GUI that combines format conversion, header inspection, checksum/hash calculation, and No-Intro DAT verification.

Features

Endianness detection from content, not file extension. Every ROM is identified as big-endian (.z64), byte-swapped (.v64), or little-endian (.n64) by inspecting the header magic bytes, with a heuristic fallback for ROMs with non-standard PI BSD DOM1 configuration bytes.

Conversion between all three formats, for a single ROM or in batch across many files/whole folders (recursive), with a live progress bar and ETA, backed by a multi-threaded worker pool.

Full ROM header parsing, including title, game code (category / unique code / region), ROM version, boot address, clock rate, libultra version, and the header's embedded check code — per the public N64brew ROM Header wiki. The game title is decoded with proper Shift-JIS (Japan)/GBK (China/iQue) support via encoding_rs, not naive ASCII/UTF-8, so Japanese and Chinese titles display correctly instead of as mojibake.

Advanced Homebrew ROM Header support: save type, RTC/region-free flags, per-port controller/accessory suggestions, and embedded metadata flag, decoded whenever the "ED" marker is present.

Legacy IPL3 CRC1/CRC2 checksum calculation (with CIC boot-chip auto-detection for 6101/6102/6103/6105/6106/7102/5101/8303/iQue/HW1, plus all 8 libdragon open-source IPL3 revisions r1-r8, fingerprinted individually rather than lumped in with 6102) compared against the value stored in the header, for compatibility with legacy emulators/ROM databases.

iQue Player & Aleck64 Arcade support: automatic detection of the prepended 32-byte container header on iQue dumps (safely parsed and noted), recognition of the 'C' destination (China / iQue), Aleck64 arcade game pak category ('Z'), and identification of Aleck64 arcade CICs (CIC-NUS-5101 and CIC-NUS-8303).

Modern hashing: CRC32, MD5, and SHA-1, for use with ROM databases. An optional "don't convert to big-endian when checking ROM info" toggle on the Single ROM tab additionally computes this same hash set against the ROM's original, native on-disk byte order (shown alongside, not instead of, the normalized hashes — No-Intro/Redump verification always uses the normalized form).

No-Intro DAT verification: load any Logiqx-style .dat/.xml file and classify a ROM as a verified good dump, a CRC-match-but-hash-mismatch ("bad dump"), or simply not present in the database. Turtle64 can hold up to 8 DAT files loaded simultaneously — one per No-Intro N64 DAT kind (N64 BigEndian, N64 ByteSwapped, 64DD, Mario no Photopie SmartMedia, iQue CDN, iQue Decrypted, Aleck64 BigEndian, Aleck64 ByteSwapped) — so a ROM is checked against every relevant DAT at once instead of requiring you to switch which single DAT is active. "Load DAT…" loads one file; "Load all DATs…" lets you multi-select several (or all 8) at once, each auto-detected and routed to its matching slot by its own < header > < name > text. The top bar shows each loaded DAT's name, version/date, and entry count. A "Check for DAT updates" button only re-reads already-loaded DAT files from disk — it never downloads anything automatically or on launch: No-Intro's DAT-o-MATIC site explicitly prohibits automated/bot access in its terms of service (and will ban the offending IP), so if you want a newer DAT you must download it yourself from No-Intro and then use this button (or just reload the file) to pick up the change.

IPL3 boot-code dumping & patching: extract a ROM's 0xFC0-byte IPL3 stage (offset 0x40-0x1000, per the N64brew IPL wiki) to a file for separate inspection, or patch in any previously-dumped IPL3 from a bootcodes folder kept next to the executable. Patching can optionally recalculate and rewrite the header's CRC1/CRC2 to match the new IPL3/CIC pairing before you save the result. All 8 libdragon open-source IPL3 revisions (r1-r8; public domain/Unlicense) are bundled in the executable and auto-seeded into bootcodes on startup, ready to patch in immediately — libdragon's production builds are GPU-bruteforced to match CIC-NUS-6102's checksum so they boot on real hardware, but Turtle64 still identifies each revision by its own fingerprint rather than reporting it as a plain 6102.

Full N64DD (64DD disk drive) support, in its own "64DD Disk" tab:

+ Content-based format detection (never by file extension) for the three known disk image formats: .d64 (SDK master disk format), .ndd (64DD Disk Dumper's LBA-ordered raw dump), and MAME's physical track-ordered format — following the layouts documented on LuigiBlood's 64dd wiki.

+ System Data / Disk ID parsing (region, disk type, retail vs. development, game code, company code, production date, IPL load address/size, ROM/RAM area LBA bounds).

+ Conversion between all three disk formats. .d64 is lossy and heavily trimmed: it keeps only the System Data, Disk ID, and the actually-used ROM/RAM Area (typically tens of MB), discarding the defect-track table, exact physical LBA sizing, and all disk padding that a full NDD/MAME dump carries (a fixed ~64.5 MB regardless of how much of the disk the game uses). Converting to .d64 permanently discards that data, and converting a .d64 back to NDD/MAME reconstructs an idealized, defect-free disk rather than the original bit-exact dump — the app warns about this in the UI whenever D64 is involved. NDD/MAME conversion, by contrast, round-trips exactly for defect-free disks (disks reporting defect/bad tracks are flagged in the UI, since the converter does not model alternate-track substitution).

+ 64DD IPL CIC identification (CIC-8303/8401/8501/etc., per LuigiBlood's 64dd CIC wiki).

+ CRC32/MD5/SHA-1 hashing of the whole disk image, plus a separate SHA-1 of just the ROM Area (matching the field jkbenaim's leotools reports for disk verification).

+ MFS (the 64DD's FAT-like RAM filesystem) volume info and a directory listing with per-file size/date (also Shift-JIS decoded, matching cartridge header titles), plus best-effort file extraction.

Export ROM/disk info to a text report, for a single ROM/disk or in batch across a whole folder — report filenames include the source file's extension (e.g. game.z64_info.txt) so same-named ROMs of different formats don't clobber each other. Conversion can also optionally write the converted output's info report immediately afterward, with no second save dialog.

(The preview release is extremely detailed, breaking down every possible data point and including multi-point ROM confidence checking to ensure each game's integrity)

(Another tool named ShellSwap, which converts game saves, is also in early alpha)
